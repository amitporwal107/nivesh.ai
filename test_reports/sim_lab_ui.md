## Summary

A read-only research surface for the frozen consecutive-session simulation runs
(`docs/ai_research/tpd3/sim_diag/PREREGISTRATION_SIM_MATRIX.md`, `SIM_DIAG_D1_D4_RESULTS.md`):

- `backend/services/sim_lab.py` — committed-snapshot loader + shape validator (the
  `services/move_odds_diagnostics.py` pattern: a missing / unreadable / wrong-schema snapshot returns `None`, so every
  route answers **503 `snapshot_unavailable`** rather than partial numbers).
- `backend/routes/sim_lab.py` — `GET /api/sim-lab/run|matrix|trades|candidates`, all
  `Depends(require_feature("sim_lab"))`, all served from the snapshot (no DB, no network, no other file).
- `backend/services/sim_lab_snapshot.json` — **A DEVELOPMENT FIXTURE, NOT RESULTS.** Every number in it is invented
  placeholder data carrying `"fixture": true`; the API passes that flag through and the page renders a loud red
  banner. The real snapshot is generated by a sibling process from the frozen run and will not carry the flag.
- `frontend-v5/src/pages/Research/SimulationLabScreen.tsx` — the V5 page (tabs: Run · Matrix · Data quality ·
  Candidate ledger · Trade audit · Reconciliation · Comparison), built to `research/sim_diag/lab_template.html`
  (the owner's design) and to `MoveOddsScreen.tsx`'s conventions for fetching / loading / error / empty states.
- `frontend-v5/src/pages/Research/index.tsx` — routed exactly like `MoveOddsScreen` (a `Screen` value behind
  `features.sim_lab`).
- `backend/server.py` — the router import + include, in the `move_odds` style.

Scope verified here: the four endpoints against the fixture (including the 503 and both 422 paths) and the V5
typecheck + production build. **No staging API call and no Playwright run** — see "Not verified".

## Contract fields I had to interpret

The `sim-lab-1` contract fixes the top-level shape but leaves several blocks open, so these choices are written down
rather than buried:

1. **`/run` carries the whole `data_quality` block, per-session rows included.** The contract says "data_quality
   summary", but the Data-quality tab has to list every session's status, flags, missing bars and special sessions,
   and the contract gives it no endpoint of its own.
2. **`/run` also returns `trade_configs`** (= `sorted(snapshot["trades"].keys())`, derived, not invented). Without it
   the page cannot populate the Trade-audit configuration selector without guessing, and `/trades` validates against
   exactly that list.
3. **`scope=replay` on `/trades` filters on `decision_date` ∈ the replay dates** — the same subsetting the owner's
   `lab_template.html` does on `signal_date`. `scope=year` returns every row the snapshot holds for that run.
4. **Units.** Rates and returns (`win_rate`, `*_per_trade`, `cost_drag`, `*_hit_rate`, `median_mfe/mae`, `net_ret`,
   `mfe_pct`, `mae_pct`, `mean_diff`, `ci95`, `max_drawdown_pct`, `return_on_capital_pct`) are read as **fractions**
   and rendered ×100, as the owner's design does. `atr_pct` is read as **already in percent** (the design prints it
   raw under an "ATR %" header). Any other number is printed as the API sent it; nothing is rescaled on a guess.
   `value20` is shown both in rupees and as ₹cr (`/1e7`), the design's own presentation.
5. **Portfolio vs fixed-notional** is decided per run entry by the presence of the capital-based fields
   (`max_drawdown_inr` / `max_drawdown_pct` / `final_equity_inr` / `return_on_capital_pct`) rather than by hard-coding
   "D and F", so a snapshot that adds another portfolio run still lands on the right side of the rule. Fixed-notional
   runs get "worst cumulative net" + "peak capital required"; only portfolio runs get a % of capital or a drawdown %.
6. **"Purpose / isolates" per run** is not a contract field. The page uses the run entry's own `purpose` (or
   `isolates`) when present and otherwise the pre-registration §4 "Isolates" column, keyed by letter; an unknown key
   renders "—". No number is ever sourced this way — it is a label.
7. **`fixture`** is an optional top-level boolean the loader passes through (the generated snapshot will not set it).
   `_`-prefixed keys are stripped from the payload, as `move_odds_diagnostics` does.
8. **Intrabar policy** is rendered from `run.intrabar_policy` if the snapshot has it (it is not in the contract's
   listed run keys) and as "—" otherwise.
