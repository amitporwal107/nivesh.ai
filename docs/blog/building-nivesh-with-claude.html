Nivesh.ai is not a weekend project. It’s two independently deployable systems: the Nivesh Application — a user-facing investing copilot with portfolio, plans, and goals, built on React 19, FastAPI, MongoDB, PostgreSQL, Redis, and a LangGraph agent with nine specialist nodes — and NIDP, the Nivesh Indian Data Platform, an isolated data lake and API platform that ingests 41 Indian market-data feeds through 28 Cloud Run ingesters, backed by TimescaleDB, Redpanda, Prometheus/Grafana/Loki, and MinIO.

That’s a lot of surface area for a small team. The kind of stack where the bottleneck is rarely ideas — it’s the hours it takes to safely touch that many moving parts without breaking something. That’s where Claude came in.

Not “AI writes code”
— AI works inside guardrails we designed

The most important decision we made was to treat Claude less like autocomplete and more like a team member who reports to a very strict process. We built that process directly into the repo — a .claude/ directory and context files that load at the start of every session.

The centerpiece is a task-intake protocol: before Claude touches anything, it classifies the work and loads the matching role guide — full-stack developer, QA, product manager, design engineer, or project manager — then applies the union of their guardrails, each with its own Definition of Done. A UI task loads the design checklist; a schema change loads the migration checklist.

On top of that sit the rules that made Claude trustworthy rather than merely fast — and they’re not suggestions in a README. They’re enforced by hooks:

HONESTY & VERIFICATION RULES — enforced .claude/settings.json · Stop hook
✓
“Changed” is not “verified.” Edited code is a hypothesis until a real command proves it.
✓
No conclusion-words without evidence in the same breath. No fixed / working / done unless that message shows the command and its real, unedited output.
✓
Mock data is loud or it’s a lie. Any stub is labeled in code and called out in prose — never passed off as a real result.
✓
Report failures, don’t paper over them. A test that fails gets shown failing.
◉

The floor isn’t willpower — it’s a Stop hook that blocks any session which edited code from ending until a verification command has actually run. The machine won’t let work be declared finished on vibes.

An AI collaborator is only as good as the environment you put it in. Encode your standards, and the tool inherits them.

What actually got shipped

Six weeks, 201 commits, across nearly every layer of the stack.

A representative slice, straight from the merge history:

  • Auth
    Authentication end to end — email OTP sign-in, self-serve magic-link validation, dropping a Gmail-only gate, plus local Mailpit dev-SMTP and staging provisioning so the flow was actually testable.
  • Mobile
    A production Android app — a Capacitor 7 build wired into CI to publish the APK, including the unglamorous debugging of scp staging dirs and streaming the artifact over an ssh channel when the off-the-shelf action failed.
  • Data
    Data-driven dashboards — an International Funds dashboard on the proper NIDP schema and price feed, and a homepage bound to a real health score instead of a hardcoded placeholder.
  • Pipeline
    A document pipeline — CAS statement PDF upload through an in-house parser, and a fix for a 500 hitting every upload from a reserved filename key colliding with Python’s LogRecord.
  • Product
    A selection framework for the Portfolio Builder, and a V5 redesign of the login and home experience.

Two things stand out. First, the range: front-end redesigns, backend bug fixes, CI plumbing, mobile builds, and data-platform work, often in the same week. Second, the nature of the wins — a lot of it is exactly the tedious, high-context, easy-to-get-wrong work that eats a small team’s time. The filename/LogRecord collision is the perfect example: one reserved-key mistake breaking all uploads, the kind of bug that costs an afternoon and gets fixed in minutes once you know where to look.

Where the productivity actually came from

Context that doesn’t evaporate.

The docs/ folder is the source of truth — architecture, API, schema, environments — and Claude reads the owner of a fact rather than guessing it. A database change starts by reading the schema doc; a claim about the feed pipeline gets checked against the real feed-status views. The AI holds the whole system in context in a way no single human on a busy day reliably does.

The verification tax, paid automatically.

The honesty rules turned “it should work” into “here’s the command and its output.” That sounds like friction; it’s the opposite — it front-loads the debugging that would otherwise surface in production. App AND data testing — the code runs and the data it produced is real and correct — became the default bar.

Parallel disciplines from one operator.

The role system let one person direct product-manager, then design-engineer, then QA thinking on the same feature without context-switching cost — there’s even a multi-agent team setup for decomposing a PRD across role subagents with a shared workspace.

What it didn’t do

Honesty is the whole point of how we ran this, so: Claude didn’t replace judgment. The intake protocol, the role definitions, the honesty hooks, the doc structure — a human designed all of that, and a human decided what was worth building and when something was actually right. When Claude hit a real blocker, the process demanded it stop and say so rather than route around it with a plausible-looking fake. That discipline is what made the speed safe. Fast and wrong would have been worse than slow.

The tool was Claude. The multiplier was the process we built around it.

The headline isn’t “AI wrote our app.” It’s that a genuinely complex, multi-system financial product got built and iterated at a pace a small team shouldn’t be able to sustain — because a well-instructed AI collaborator absorbed an enormous amount of the high-context, verification-heavy, cross-layer grunt work, inside guardrails that kept it honest. The gain wasn’t magic. It was the compounding of a hundred afternoons not lost to reserved-key bugs, scp misconfigurations, schema mismatches, and “wait, did that actually deploy?”
