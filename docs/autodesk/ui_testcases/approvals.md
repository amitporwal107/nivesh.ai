# Approval queue (screen 05) — UI test cases (written before the screen code)

Design: `docs/autodesk/design/prototype/TDApprovals.dc.html`. Screen: `frontend-v5/src/autodesk/screens/Approvals.tsx`.
Spec: `frontend-v5/e2e/tests/autodesk-approvals.spec.ts` (route mocks from `autodesk-fixtures-approvals.ts`, shapes of
the real API). Request contracts: `frontend-v5/e2e/fixtures/autodesk/requests/approvals.json`.

Layer: E = Playwright against the production build with route mocks; C = the request body the UI sends equals a
contract that the backend test posts to the real FastAPI app.

Data sources: `GET /approvals?pending=true` (desk queue = rows with `simulation_id == null`), `GET /approvals?limit=100`
(decided rows), `GET /approvals/{id}`, `GET /trade-plans?limit=200` (instrument / strategy of decided rows),
`GET /trade-plans/{trade_id}?version={plan_version}` (body + `plan_hash` + `latest_risk_assessment` + `approvals`),
`GET /trade-plans/{trade_id}/versions`, `GET /risk/assessments/{id}`, `GET /risk/portfolio/{account_id}`,
`GET /signals/{signal_id}`, `GET /accounts`, `GET /desk/status` (STOP_NEW_ENTRIES).
