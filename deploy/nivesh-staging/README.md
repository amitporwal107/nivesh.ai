# nivesh-staging — Portfolio Ingestion staging environment

A fully isolated staging stack for the new `portfolio_ingestion` service. Runs
on the existing `nivesh-app-vm` alongside production, but with separate
containers, network, volumes and ports. Never touches any prod file.

## Topology

```
                    Cloudflare (proxy)
                    │
staging.niveshcopilot.com ─── 34.47.250.214:8443 ── nivesh-staging-nginx
                                                       │ (proxy_pass)
                                                       ▼
                                       nivesh-staging-ingestion (FastAPI :8002)
                                                       │
                          ┌────────────────────────────┼─────────────────────────────┐
                          ▼                            ▼                             ▼
              nivesh-staging-postgres        nivesh-staging-mongo         nivesh-staging-redis
              (127.0.0.1:5532)               (127.0.0.1:27117)            (127.0.0.1:6479)

  Outbound (read-only) → prod NIDP DaaS: https://data.niveshcopilot.com
```

## Files

| File | Purpose |
|---|---|
| `docker-compose.staging.yml` | Stack definition (5 services, isolated network) |
| `nginx-staging.conf` | Edge nginx vhost for `staging.niveshcopilot.com` |
| `Dockerfile.ingestion` | Image for the new FastAPI service |
| `.env.staging.example` | Env template (real `.env.staging` lives on the VM, generated by bootstrap) |
| `bootstrap-staging.sh` | One-time host setup (dirs, env file, port conflict check) |
| `redeploy-staging.sh` | Pull + build + restart loop |

## First-time bring-up

```bash
# On nivesh-app-vm
sudo mkdir -p /opt/nivesh-staging
sudo git clone https://github.com/<org>/<repo>.git /opt/nivesh-staging/repo
sudo bash /opt/nivesh-staging/repo/deploy/nivesh-staging/bootstrap-staging.sh
sudo bash /opt/nivesh-staging/repo/deploy/nivesh-staging/redeploy-staging.sh
```

Verify from the VM:

```bash
curl -k --resolve staging.niveshcopilot.com:8443:127.0.0.1 \
     https://staging.niveshcopilot.com:8443/api/healthz
```

## Going public (manual, one-time)

These are GCP + Cloudflare actions outside this repo. Until both are done the
stack only answers on 127.0.0.1:8443 inside the VM.

1. **Open GCP firewall for port 8443.**

   ```bash
   gcloud compute firewall-rules create allow-staging-https \
     --network=default \
     --direction=INGRESS \
     --action=ALLOW \
     --rules=tcp:8443 \
     --source-ranges=173.245.48.0/20,103.21.244.0/22,103.22.200.0/22,103.31.4.0/22,141.101.64.0/18,108.162.192.0/18,190.93.240.0/20,188.114.96.0/20,197.234.240.0/22,198.41.128.0/17,162.158.0.0/15,104.16.0.0/13,104.24.0.0/14,172.64.0.0/13,131.0.72.0/22 \
     --description="Cloudflare → nivesh-staging on 8443"
   ```

   (Source ranges = Cloudflare's published edge IPs. Update from
   `https://www.cloudflare.com/ips-v4` if needed.)

2. **Add the DNS record on Cloudflare** for the niveshcopilot.com zone:

   ```
   Type: A
   Name: staging
   Value: 34.47.250.214
   Proxy: ON (orange cloud)
   ```

3. **Add a Cloudflare Origin Rule** routing `staging.niveshcopilot.com` → origin
   port 8443 (Rules → Origin Rules → Override → Destination Port: 8443).

4. **Flip the nginx bind on the VM** from localhost-only to public:

   ```bash
   sudo sed -i 's/^PI_NGINX_BIND_ADDR=.*/PI_NGINX_BIND_ADDR=0.0.0.0/' /opt/nivesh-staging/.env.staging
   sudo bash /opt/nivesh-staging/repo/deploy/nivesh-staging/redeploy-staging.sh
   ```

5. **Test from outside the VM:**

   ```bash
   curl https://staging.niveshcopilot.com/api/healthz
   ```

## Teardown

```bash
sudo docker compose --env-file /opt/nivesh-staging/.env.staging \
     -f /opt/nivesh-staging/repo/deploy/nivesh-staging/docker-compose.staging.yml down
# Data is preserved under /opt/nivesh-staging/data/. Add -v to wipe.
```
